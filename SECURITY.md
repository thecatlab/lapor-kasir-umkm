# Security review

Reviewed on 2026-09-22. Scope: all four originally tracked files and 28 historical file blobs reachable from locally available Git refs. Historical review used credential-pattern searches and file inspection; it is not proof that every possible secret is absent. Remote permissions, deployed code, Drive contents, Sheets data, and inaccessible Git refs were not audited.

## Findings and remediation

| Severity | Finding | Repository remediation |
| --- | --- | --- |
| High | The write handler did not authenticate callers. Anonymous deployments could accept unauthorized reports and consume owner resources. | Require a server-configured random access token before locking, uploading, or writing. Request it at runtime, keep it in memory, and fail closed if unconfigured. Make the setup helper private to browser RPC. |
| High | Expense text, notes, and saved values entered HTML; notes also entered the screenshot DOM. | Escape dynamic HTML text/attributes and bind expense deletion with an event listener instead of interpolated JavaScript. |
| High | Caller-controlled spreadsheet strings could become formulas. | Escape formula-like strings at each report/expense row write, preserve numeric types, and validate inputs against object/array coercion. |
| Medium | Callers selected upload folders; sizes/types were unchecked. | Use server properties for the folder, limit request/image sizes and expense counts, validate fields, filenames, base64, and PNG signatures. This is not a full image decoder or malware scan. |
| Medium | Save messages lacked origin/sender checks; backend responses used wildcard target origins. | Validate Google origins and submission iframe ancestry, retain random request correlation, and reply to exact configured frontend origins. |
| Medium | Production deployment and Drive identifiers were committed. | Move them out of tracked source into local frontend configuration/server properties and document migration. Identifiers are not passwords; removing them is not access control. |
| Medium | Backend errors could disclose service details; inaccessible spreadsheets could silently cause replacement storage. | Return bounded public errors and preserve the configured spreadsheet ID on failure. |
| Low | External executable scripts lacked integrity checks; Tailwind was unversioned. | Replace the Tailwind runtime script with a committed stylesheet generated by Tailwind 3.4.17. Pin html2canvas 1.4.1 with SHA-384 integrity and anonymous CORS. |
| Informational | Business-specific identity and obsolete revision comments were published. | Use neutral public branding, keep useful implementation comments, and expand setup/usage documentation. |
| Informational | No ignore rules protected local configuration/report artifacts. | Ignore local deployment settings, common credentials, private report folders, and development artifacts. |

No API keys, private keys, passwords, transaction exports, customer records, or personnel records were found in the reviewed tracked files/history. Business names and service identifiers were present. No inappropriate personal content was identified; presentation issues were the minimal README, organization-specific branding, and stale revision comments. The legacy browser storage key remains to preserve drafts.

## Deployment follow-up (2026-09-23)

The updated backend was deployed as version 5 at the existing web-app URL. The original spreadsheet and Drive folder IDs remain configured in Script Properties, together with the allowed frontend origin and an owner-saved access token. No token was committed or included in frontend configuration.

GitHub Pages now deploys through Actions. Its build supplies public `config.js` from the repository variable and publishes only the intended browser assets; backend source is excluded. The original Apps Script endpoint is unchanged.

The live site's authenticated, read-only storage check returned **Koneksi Siap**, confirming the real iframe response flow and access to the configured spreadsheet's required tabs and the existing Drive folder. After the owner explicitly requested a production test, a clearly labeled synthetic report using a separate future date was saved through the live frontend. Its report row, linked expense, totals, and viewable PNG in the original folder were verified. A second submission returned the duplicate response and reused the same submission and image instead of adding records.

With the owner's cleanup approval, the exact test report/expense cells were cleared, the PNG was moved to the owner's Drive bin, and the synthetic browser draft was reset. Readback confirmed the pre-existing sheet values and cell formatting were unchanged. The test image is recoverable from the bin while retained by Drive.

The deployment manager showed one active deployment (updated in place) and three archived deployments. Review any other projects or deployments separately. Prior identifiers remain in history, forks, and caches; history was not rewritten. Sheets/Drive sharing and historical data still need an owner review for unexpected entries/formulas. This review does not establish whether the old endpoint was abused; existing data and formulas were not modified.

A fresh clone still needs its own configuration; see [README.md](README.md). Never publish the working directory, `.git`, or an access token.

## Remaining limitations

- The shared token authorizes submissions, not individual cashiers. Distribute it privately and rotate it on exposure or staff access changes. No per-user audit identity, per-token rate limiting, or comprehensive quota-exhaustion protection is implemented.
- The origin field is client-supplied and can be forged outside browsers. The token authenticates requests; origin checks constrain browser response delivery.
- Drafts are unencrypted in browser storage. Trusted same-origin scripts and extensions may access drafts/in-memory tokens. Integrity checks reduce CDN substitution risk but cannot make third-party JavaScript intrinsically trustworthy.
- html2canvas and Google Fonts remain external dependencies. Tailwind is built locally; its original CDN does not support the cross-origin fetch needed for script integrity checking. A strict Content Security Policy requires a separate refactor of inline scripts/event handlers.
- Authorized users can submit incorrect business figures. Calculations were kept compatible; this is not an accounting audit or server-side reconciliation engine.
- Sheets writes and Drive uploads are not transactional. Failures may leave partial writes or orphaned images, as in the existing integration.
- Exported reports, clipboard contents, and shared messages expose business information to their recipients. Keep operational exports outside the public repository.
- Live verification found **Anyone with the link** access on the production spreadsheet and the newly uploaded PNG. The app's access code protects its submission endpoint, not direct Sheets/Drive links. Sharing permissions were not changed during testing; the owner should review whether link access is intentional before treating these records as private.

## Verification

Run `node --test tests/*.test.cjs`. Tests cover authentication before side effects, exact origin checks, input/size limits, literal spreadsheet text, server-owned upload destinations, error redaction, response framing, duplicates/revisions, original calculations, browser escaping, the read-only connection check, and the Pages artifact/configuration.

Verification completed during this review:

- All 18 Node tests passed, including the authenticated save → duplicate screenshot recovery → revised report flow with mock Sheets/Drive services.
- Desktop and 390px mobile browser checks passed for all four tabs, reconciliation totals, persisted drafts after refresh, literal malicious expense/notes text, and PNG creation (750px desktop and 500px mobile exports).
- Browser checks passed for the access-code dialog, memory-only token handling, mocked authenticated submission, forged-origin rejection, response cleanup, and local PNG fallback after a simulated cloud failure.
- The local server returned 404 for Git metadata, environment files, backend source, and report paths. Patch whitespace checks passed.

The automated/browser security tests used synthetic data with local mocks. On 2026-09-23, the owner separately authorized a bounded production save and duplicate test, followed by cleanup as described above. This verified authentication, the real iframe response, report and expense writes, correct saved totals, PNG upload to the original folder, and duplicate handling. It does not establish that every failure mode, revision path, browser, mobile share target, or historical record is correct. Future synthetic tests should use mocks or a dedicated test deployment unless the owner explicitly authorizes another production test.

For suspected vulnerabilities, contact the owner privately through an available verified channel. Do not post access codes, production URLs, report data, or exploit details in public issues.
